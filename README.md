# dmnet

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

`dmnet` is the umbrella [DMOD](https://github.com/choco-technologies/dmod)
repository for userspace-facing networking on a DMOD system: the `networkd`
service that keeps every registered interface pumped, and the `ifconfig`/`ip`
CLIs used to inspect and control interfaces and routes. The actual protocol
stack (interfaces, routing, ARP, IP framing/dispatch) lives in their own
sibling repositories and is pulled in as a dependency - this repo does not
implement any of it itself.

```
┌───────────────────────────────────────────────────────────────┐
│                            dmnet                                │
│                                                                   │
│   tools/ifconfig      tools/ip         services/networkd        │
│   (interface CLI)   (routing CLI)   (per-interface RX pump)     │
└─────────┬────────────────┬───────────────────┬─────────────────┘
          │                │                   │
          ▼                ▼                   ▼
     ┌─────────┐      ┌─────────┐        ┌─────────────┐
     │ dmnetif │      │ dmroute │        │ dmnetbridge  │
     │ ifaces  │◄─────┤  routes │◄───────┤ send/receive │
     └─────────┘      └─────────┘        └──────┬───────┘
                                                 │
                                           ┌──────┴───────┐
                                           │    dmarp     │
                                           │ MAC resolve  │
                                           └──────────────┘
```

`dmip`/`dmarp`/`dmnetbridge`/`dmnetif`/`dmroute` used to live under this
repo's `lib/` directory; they have since been split out into their own
repositories (see the git history and each repo's own README) and are now
fetched via `dmod_link_modules(...)`, the same way any other external DMOD
dependency is. `lib/` itself is kept only as an (empty) subdirectory
`add_subdirectory`'d from the top-level `CMakeLists.txt`.

## What's actually in this repo

| Path                  | Type                | What it does                                                                                                     |
|------------------------|----------------------|--------------------------------------------------------------------------------------------------------------------|
| `include/`, `src/`     | Library module (`dmnet`) | Template/scaffold module (`dmnet_create`/`_destroy`/`_is_valid`) generated by `dmod`'s `new-module.sh` - not wired into anything else in this repo yet. See [API](#api) below. |
| `services/networkd/`   | Application module  | Spawns one thread per interface already known to `dmnetif` at startup, each running `dmnetbridge_handle_netif_rx()`. See [services/networkd/README.md](services/networkd/README.md). |
| `tools/ifconfig/`      | Application module  | CLI to list/create/configure `dmnetif`-registered interfaces (`ifconfig <iface> up/down/mtu/...`). See [tools/ifconfig/README.md](tools/ifconfig/README.md). |
| `tools/ip/`            | Application module  | CLI to list/add/remove routes in `dmroute`'s table (`ip route ...`). See [tools/ip/README.md](tools/ip/README.md). |
| `tools/netctl/`        | (scaffold only)      | No module content yet - not added to `tools/CMakeLists.txt` (see its comment there).                              |
| `lib/`                 | (empty)              | Historical location of `dmip`/`dmarp`/`dmnetbridge`/`dmnetif`/`dmroute`, now split into their own repos.           |

Each subdirectory under `services/` and `tools/` is its own DMOD module with
its own `CMakeLists.txt`, `docs/`, and `README.md` - read those for the
details of that specific module. This top-level README only covers what's
common across the repo and the top-level `dmnet` library module itself.

## Architecture

- **`dmnet` (this repo's own library module)** is presently a scaffold: an
  opaque `dmnet_t` handle with `_create()`/`_destroy()`/`_is_valid()`,
  generated by `dmod`'s module template and not yet replaced with real
  functionality (see the doc comment at the top of
  [`include/dmnet.h`](include/dmnet.h)). It builds and tests standalone but
  nothing else in this repo depends on it.
- **`networkd`** owns *reading* every interface. `dmnetbridge_handle_netif_rx()`
  is the only code path allowed to call `dmnetif_receive()` on a given
  interface once `networkd` has started pumping it - a second concurrent
  reader would race it. This is what lets `dmip`/`dmudp` receive a packet
  from *any* interface without ever naming one themselves.
- **`ifconfig`** and **`ip`** are thin CLIs: `ifconfig` never touches devfs
  paths or `dmdrvi` directly, only `dmnetif`'s interface-name API; `ip`
  never touches `dmroute`'s internals directly, only its public
  add/remove/lookup/`for_each` API. Both are Application-type modules,
  loaded/run/unloaded on demand rather than kept resident (see each tool's
  own README for why their tests use `Dmod_RunModule()` instead of linking
  against them).
- **Sending** a packet (route lookup, ARP resolution, Ethernet framing) and
  **receiving** one (the pump loop `networkd` drives, dispatched to every
  interested protocol module via the `packet_received` DIF) both happen in
  `dmnetbridge`, not in this repo - see
  [dmnetbridge's own README](https://github.com/choco-technologies/dmnetbridge)
  for that side of the architecture.

## Building

`dmnet`'s `CMakeLists.txt` fetches `dmod` itself via CMake's
`FetchContent` (defaulting to the `develop` branch), so no other
repository needs to be checked out first to build the top-level `dmnet`
library module. Building `networkd`, `ifconfig`, or `ip` additionally
requires `dmnetif`/`dmroute`/`dmarp`/`dmnetbridge` to be resolvable at
link time - `dmod_link_modules(...)` in each module's own `CMakeLists.txt`
handles fetching those.

### Using CMake

```bash
mkdir -p build
cd build
cmake ..
cmake --build .
```

This builds the top-level `dmnet` library module, `networkd`, `ifconfig`,
and `ip` (plus each one's test module). Pass
`-DDMOD_DIR=/path/to/local/dmod` to build against a local `dmod` checkout
instead of fetching it from GitHub. Build a single target with
`cmake --build . --target <name>` (e.g. `ifconfig`, `test_dmnet`).

### Using Make

```bash
make DMOD_MODE=DMOD_MODULE DMOD_DIR=/path/to/dmod
```

The Makefile requires an existing `dmod` checkout (there is no
`FetchContent` equivalent for Make) and builds the top-level `dmnet`
module itself, not `services/`/`tools/` or the test suite.

## Testing

Every module in this repo (`dmnet`, `networkd`, `ifconfig`, `ip`) has its
own `tests/` directory built with `dmod_add_test()`, registering
`DMOD_TEST_STEP()` cases run through `dmod_loader`:

```bash
export DMOD_DMF_DIR=$(pwd)/build/dmf
dmf-get install -d ${DMOD_DMF_DIR}/test_dmnet-local.dmd -y
dmod_loader build/dmf/test_dmnet.dmf
```

`test_ifconfig`/`test_ip` drive their module through `Dmod_RunModule()`
rather than linking against it directly (Application-type modules can't be
loaded as another module's dependency); `test_networkd` and `test_dmnet`
follow the ordinary library/dependency test pattern. See each module's own
README/`docs/` for what its test suite actually covers.

## API

The top-level `dmnet` library module currently exposes only the scaffold
handle API below (see [Architecture](#architecture) - nothing else in this
repo depends on it yet). For `networkd`'s, `ifconfig`'s, and `ip`'s actual
functionality, see their own READMEs linked in the table above.

| Function            | Description                                                                 |
|----------------------|-------------------------------------------------------------------------------|
| `dmnet_create()`      | Allocate a new `dmnet_t` instance. Returns `NULL` on allocation failure.     |
| `dmnet_destroy(handle)` | Free an instance created by `dmnet_create()`. Safe to call with `NULL`.   |
| `dmnet_is_valid(handle)` | `true` if `handle` is a valid, non-`NULL` instance.                     |

```c
#include "dmnet.h"

dmnet_t handle = dmnet_create();
if (dmnet_is_valid(handle))
{
    /* ... */
}
dmnet_destroy(handle);
```

Full documentation (generated from this same scaffold) is in
[docs/api-reference.md](docs/api-reference.md), viewable via
`dmf-man dmnet api`.

## Usage example: bringing up an interface and routing through it

Putting `ifconfig` and `ip` together against a freshly registered
interface (see each tool's own README for the full command reference):

```bash
# Register an interface backed by a devfs node, then bring it up
ifconfig eth0 create /dev/eth0
ifconfig eth0 up

# dmroute adds a "connected" route for eth0's own subnet automatically
# once it has an address - no "ip route add" needed for that part
ip route

# Add a default route via the LAN gateway
ip route add default via 192.168.1.1 dev eth0

# networkd (already running as a service) is now pumping eth0's RX side;
# any dmip-based protocol module receives frames from it without knowing
# eth0 exists
```

## Dependencies

- [`dmnetif`](https://github.com/choco-technologies/dmnetif) - interface
  registry and frame I/O. Used by `ifconfig`, `networkd`.
- [`dmroute`](https://github.com/choco-technologies/dmroute) - routing
  table. Used by `ip`, transitively by `networkd` via `dmnetbridge`.
- [`dmarp`](https://github.com/choco-technologies/dmarp) - MAC address
  resolution. Used transitively by `networkd` via `dmnetbridge`.
- [`dmnetbridge`](https://github.com/choco-technologies/dmnetbridge) -
  send/receive glue between `dmip` and the interface/routing/ARP layer.
  Used by `networkd`.
- `dmlist`, `dmosi` - list bookkeeping and threading, used by `networkd`.
